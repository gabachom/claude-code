# seo-validity — 効果を「信じる」のではなく「測る」

合計流入・合計問い合わせは、知名度・SNS・営業活動の効果が混ざるため施策のKPIにできない。このスキルは**手法の効果だけを取り出して判定する**計測基盤を作る。

## When to invoke(発動条件)

- 「この施策の効果を測りたい」「効果検証の仕組みを作って」
- 「ブランド検索を除外して分析して」「指名検索とそれ以外を分けて」
- 「どの記事を伸ばす/消すべきか判定して」
- 新しいSEO/AIO施策を始める**前**(事前登録のため)

## 前提

- Google Search Console 登録済み+APIのサービスアカウント認証(自動レポート用)
- GA4 導入済み

## 手順

### Step 1: 施策の事前登録(打つ前に書く)

施策ごとに `experiments/YYYY-MM-DD-<施策名>.md` を作成:

```markdown
# 施策: <名前>
- 開始日 / 判定日(例: 90日後)
- 仮説: <この施策で何がどう変わるはずか>
- 狙う非ブランドクエリ(5〜10個)と現在順位・現在クリック数
- 成功基準(例: クエリ群の平均順位20位以内 AND 非ブランドクリック週50)
- 外れた場合の次アクション
```

**判定日まで基準を変更しない。** 後付けの成功解釈を構造的に防ぐのが目的。

### Step 2: ブランド/非ブランド分離レポート

1. 指名クエリの正規表現を定義(社名・個人名・サービス名+表記ゆれ。例: `(サンプル|sample|さんぷる|山田太郎)`)
2. GSC APIで週次取得し、**非ブランドのみ**のクリック・表示・平均順位を `reports/gsc-nonbrand-YYYY-Www.csv` に記録
3. KPIダッシュボードには非ブランド系列だけを載せる(ブランド系列は「発信の効果」として別管理)

```
実装: scripts/gsc_nonbrand.py
  searchanalytics.query(dimensions=[query,page],
    dimensionFilterGroups=[{filters:[{dimension:QUERY, operator:EXCLUDING_REGEX, expression:BRAND_RE}]}])
  → 週次CSV追記 + 前週比をSlack通知(GitHub Actions cron: 月曜朝)
```

### Step 3: UTM規律(流入起点の分離)

- SNS投稿・メール・配布資料・プロフィール欄のリンクに必ずUTMを付ける(`utm_source=x|newsletter|whitepaper...`)
- 問い合わせ・診断フォームに「初回接点」(GA4のfirst_user_source)を自動記録し、リード管理シートに列を持つ
- これで「検索起点リード(手法の成果)」と「SNS起点リード(知名度の成果)」が分離できる

### Step 4: 記事コホート測定(公開28日判定)

各記事を公開28日後に自動判定し `reports/article-cohort.csv` に追記:

| 指標 | 取得元 |
|---|---|
| インデックス済みか | GSC URL Inspection API |
| 表示回数・非ブランドクリック | GSC(Step 2のフィルタ適用) |
| アシスト転換(診断・資料請求) | GA4 |

### Step 5: 刈り込み判定(月次)

コホートデータから機械的に判定:

- **伸ばす**: 順位4〜10位のクエリ保有 → 一次情報追記(seo-growth へ)
- **直す**: 表示多×CTR低 → タイトル・冒頭リライト
- **削る**: 28日で表示ほぼゼロ、かつ内部リンクのハブ機能もない → 類似記事へ301統合または削除。負け記事の放置はサイト全体の品質評価を薄める
- 判定結果はPRとして提案し、削除は人が承認してから実行する

## 完了チェックリスト

- [ ] 進行中の施策すべてに事前登録ファイルがある
- [ ] 非ブランド週次レポートが自動で届く
- [ ] 全流入リンクにUTM・リードに初回接点が記録される
- [ ] 記事コホートCSVが自動更新され、月次の刈り込み判定が回っている
