# blog-automation — ブログを「毎日・自動」で増やす

検索で一番効くのは、良い記事を出し続けること。でも毎日手では書けないので、パイプラインを組む。
目標体制: **毎朝2本の本流記事+毎夕1本のニュース記事=毎日3本**+週次で既存記事リライト。

## When to invoke(発動条件)

- 「ブログを自動化して」「記事を毎日自動で出したい」
- 「SEO記事を書いて」(単発執筆にもStep 2〜4を単体適用できる)
- LP公開後、検索流入を増やしたいとき

## パイプライン7ステップ

```
①ネタ収集 → ②AIが執筆 → ③サムネ生成 → ④AIが校正(安全ゲート) → ⑤自動で公開 → ⑥検索へ通知 → ⑦日次レポート
```

**設計原則: 書くAIとチェックするAIを分ける。** 同じコンテキストで書いて自己チェックさせると甘くなる。ステップ④は独立プロセス(別セッション/サブエージェント)で `references/safety-gate.md` の基準だけを見て合否判定する。

### ① ネタ収集

- 種は3系統: (a) 狙うキーワードのサジェスト・関連語 (b) Search Consoleの実クエリ(→ seo-growth) (c) 業界ニュースRSS
- ネタは `content/queue/` にMarkdownチケットとして積む(タイトル案・狙いクエリ・参考URL)

### ② AI執筆

- ハブ&スポーク: 「完全ガイド」級ハブ記事を先に立て、スポーク記事は必ずハブへ内部リンク
- 記事frontmatterに `title / description / pubDate / author / tags / 狙いクエリ` を必須化
- 一次情報(自社実績・検証結果)を最低1箇所入れる。**AIの一般論だけの記事は出さない**
- 本文末に関連記事リンク3本+LPのCTAを自動挿入

### ③ サムネ生成

- 標準フローは**APIキー不要のSVG生成**(タイトル文字入れテンプレをコードで生成)→ **必ずPNGに変換**して出力
  (SVGのままだとXやSlackに貼ったとき画像が表示されない。`npx sharp-cli -i thumb.svg -o thumb.png`)
- 画像生成AIを使う場合のみAPIキーが必要

### ④ 安全ゲート(公開前チェック)

`references/safety-gate.md` の基準で合否判定。**不合格は公開せず `content/rejected/` へ**、理由付きでレポートに載せる。

### ⑤ 自動公開

- 合格記事を `content/blog/` へ移動 → git commit → push → ホスティングが自動デプロイ
- スケジュールは GitHub Actions cron(`references/pipeline.md` に構成例)

### ⑥ 検索へ通知

- sitemap更新(実更新日ベースのlastmod)
- IndexNow へ ping(Bing等)+ Search Console の sitemap 再送信

### ⑦ 日次レポート

- 毎晩: 公開本数 / 不合格本数と理由 / PV / 順位変動 をSlack(またはメール)に1通
- 人の作業はこの確認だけ(週90分目安)

## 週次リライト

週1回、公開済み記事から「表示回数が多いのにCTRが低い」記事を選び、タイトル・冒頭・FAQ追記をリライト(選定は seo-growth スキルのデータで)。

## 構築手順

1. Astroプロジェクトに `@astrojs/sitemap` + Content Collections(`content/blog/`)を設定
2. `references/pipeline.md` のワークフローを `.github/workflows/` に配置し、`ANTHROPIC_API_KEY` をSecretsに登録
3. 最初の2週間は**自動公開をOFF**(PRとして出して人がマージ)にし、安全ゲートの精度を確認してから自動化する
