# content-map.md — プレースホルダ一覧と詰め替えガイド

`lp-template.astro` 内の `{{...}}` を、ここの表に従って自社情報へ差し替える。
**全項目を埋めてから置換を始める**こと(途中で置換すると漏れが出やすい)。

## 1. 基本情報(必須)

| プレースホルダ | 説明 | 例 |
|---|---|---|
| `{{COMPANY_NAME}}` | 運営会社名 | 株式会社サンプル |
| `{{SERVICE_NAME}}` | サービス/商品名 | ◯◯導入支援 |
| `{{SITE_URL}}` | 公開URL(末尾スラッシュなし) | https://example.com |
| `{{PRIMARY_KEYWORD}}` | 1位を狙う購買直結キーワード | ◯◯ 法人導入 |
| `{{META_TITLE}}` | titleタグ。PRIMARY_KEYWORDを先頭付近に | ◯◯法人導入支援｜研修・コンサルティング｜株式会社サンプル |
| `{{META_DESCRIPTION}}` | 120字前後。数字と提供価値を入れる | ◯◯で業務自動化を実現。研修・コンサルで一気通貫支援。導入実績◯社。 |

## 2. ヒーロー(最重要セクション)

| プレースホルダ | 説明 |
|---|---|
| `{{HERO_COPY}}` | 一言で「誰の何がどうなるか」。体言止め推奨 |
| `{{HERO_SUB}}` | 補足1〜2文。具体的な提供内容 |
| `{{HERO_CTA_PRIMARY}}` | 最前面ボタン。**心理的ハードルが最も低い入口**にする(例:「1分で無料AI診断」)。資料請求より診断が動く |
| `{{HERO_CTA_SECONDARY}}` | 第2ボタン(例:「無料相談・お問い合わせ」) |
| `{{HERO_STATS_*}}` | 実績数値3〜4個(導入社数・事例数・受講者数など)。**盛らない。実数のみ** |

## 3. 著者・信頼情報(E-E-A-T の核)

| プレースホルダ | 説明 |
|---|---|
| `{{AUTHOR_NAME}}` / `{{AUTHOR_NAME_EN}}` | 記事・サイトの著者(代表者など実在の個人) |
| `{{AUTHOR_TITLE}}` | 肩書 |
| `{{AUTHOR_BIO}}` | 経歴・実績。数値で語る |
| `{{AUTHOR_X_URL}}` / `{{AUTHOR_YOUTUBE_URL}}` | SNSプロフィールURL(構造化データ sameAs に入る) |
| `{{CLIENT_LOGOS}}` | 顧客ロゴ画像(**掲載許諾を必ず確認**) |

## 4. サービス・事例

| プレースホルダ | 説明 |
|---|---|
| `{{PILLAR_1..5}}` | サービスの柱(5本)。名前+3行説明 |
| `{{CASE_1..N}}` | 活用事例。多いほど強い(元記事は32本)。画面イメージ付きが理想 |
| `{{TESTIMONIAL_*}}` | 導入企業の声(社名・担当者名は許諾のうえ) |

## 5. FAQ(構造化データと連動)

`{{FAQ_1..7}}` — 質問と回答のペア。**Search Console の「実際に検索されたクエリ」から作るのが最強**(公開後に seo-growth スキルで追加する)。初期は営業でよく聞かれる質問7個。

## 6. 計測・連絡先

| プレースホルダ | 説明 |
|---|---|
| `{{GA_MEASUREMENT_ID}}` | Google Analytics 4 の測定ID(G-XXXX)。未定なら空でよい |
| `{{CONTACT_EMAIL}}` / `{{CONTACT_FORM_URL}}` | 問い合わせ先 |
| `{{BOOKING_URL}}` | 日程調整URL(lead-capture スキル参照) |
| `{{ALTERNATE_NAMES}}` | 表記ゆれ配列(カタカナ・英語・略称)。JSON-LD alternateName に入る |

## 置換の実行

エディタの一括置換ではなく、Claude Code に「content-map の値で lp-template.astro のプレースホルダを全置換して」と依頼し、最後に必ず:

```bash
grep -n "{{" src/pages/index.astro   # 出力ゼロ = 置換完了
```
