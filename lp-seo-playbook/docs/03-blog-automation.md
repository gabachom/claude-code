# フェーズ3: ブログ自動化(24時間働く営業を作る)

使うスキル: **blog-automation**

検索で一番効くのは良い記事を出し続けること。でも毎日は無理なので自動化する。
元記事の到達点: **毎朝2本+毎夕1本=毎日3本が自動で積み上がり**、週次で既存記事をリライト。公開済み59本・28日で1,269PV・人の作業は確認だけ(週90分)。

## 手順

1. **ブログ基盤を追加**: LPと同じAstroプロジェクトに `/blog/` を追加(Content Collections)。LPのセクション13(最新記事)と接続
2. **ハブ記事を人が監修して1本立てる**: 「◯◯完全ガイド」級の長文。以後の全記事がここに内部リンクする
3. **ネタキューを作る**: 狙いクエリのサジェスト+営業でよく聞かれる質問から30本分のネタチケットを `content/queue/` に積む
4. **パイプライン設置**: `references/pipeline.md` のワークフロー3本を `.github/workflows/` に配置、Secrets登録
5. **段階導入**: 最初の2週間は自動公開OFF(PRで出して人がマージ)→ 安全ゲートの合格判定が信頼できるようになってから自動公開ON

## 設計のミソ

- **書くAIとチェックの仕組みを分ける**。安全ゲート(safety-gate.md)は執筆と別プロセスで、基準だけを見て合否判定。人の作業は「確認だけ」になる
- サムネはSVG生成(APIキー不要)→ **必ずPNG変換**(X/Slackで表示されるように)
- 不合格記事は捨てずに `content/rejected/` へ。理由を見てプロンプトを改善する
