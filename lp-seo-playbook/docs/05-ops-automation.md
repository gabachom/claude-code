# フェーズ5: 問い合わせ後の自動化と検索データ運用

使うスキル: **lead-capture**(自動化) / **seo-growth**(検索データ運用)

LPは公開して終わりではない。大事なのは問い合わせが来た**後**と、検索の**実データで育て続ける**こと。

## 5-1. 問い合わせ後の自動化(lead-capture)

```
診断・フォーム送信 → 自動返信メール → お客様が日時選択 → Zoom URL自動発行 → 担当へSlack通知
```

- 担当の出し分け(問い合わせ種別→予約ページ・通知先を自動振り分け)
- 通知の二重化(Slack+確定メール解析の予備ルート・署名検証付き)— 1本の経路を信用しない
- スパム対策(bot対策・連投制限・ハニーポット)
- フォーム必須項目は3個まで
- リード管理ファネル(問い合わせ→対応中→商談済み→案件化)

**自動化の線引き**: 自動はリード獲得〜面談予約まで。商談(面談・提案・クロージング)は人。「人に会うまで」を自動で最短化し、人は人にしかできない対話に集中する。

## 5-2. 検索の実データで育てる(seo-growth)

公開2週間後から、Google Search Console のデータで勘ではなくデータで直す:

1. **主力ページの強化**: 表示回数トップのページに実クエリ由来のFAQを追加(FAQ構造化データ併記)
2. **表記ゆれ回収**: 別表記を alternateName に登録
3. **順位監視の自動化**: 毎週月曜、主要キーワードの順位を自動記録し、下落があればSlackアラート。「下がった瞬間に気づける」体制を人手ゼロで
4. **週次リライト**: 表示多×CTR低、順位4〜10位の記事を優先改稿

## 落とし穴(元記事が実際に踏んだもの)

- sitemapのlastmodがデプロイごとに全ページ更新 → Googleへの虚偽申告状態。実更新日ベースに即修正
- ブログサムネがSVG → X/Slackで画像が出ない。全44枚をPNGに一括変換(Claude Codeにやらせる)
