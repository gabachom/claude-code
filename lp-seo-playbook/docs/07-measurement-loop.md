# フェーズ6(v2): 測定駆動ループ — 「信じる」から「測る」へ

使うスキル: **seo-validity**(計測・判定) / **aio-optimization**(AI引用層) / **blog-automation**(情報利得ゲート版)

元記事の運用は Build → Publish → Watch(順位) の**開ループ**。順位は見ているが、「その施策が効いたのか」「知名度が効いたのか」を分離できない。v2はこれを閉ループにする:

```
① 事前登録 → ② 質ゲート付き出荷 → ③ 交絡除去した計測 → ④ 判定(伸ばす/直す/削る) → ①へ
   (仮説宣言)     (情報利得ゲート)      (非ブランドのみでKPI)     (週次/月次)
```

## ① 事前登録(Pre-registration)

施策を打つ**前**に、seo-validity スキルのテンプレで宣言してから作る:

- 狙う非ブランドクエリ(5〜10個)と現在順位
- 期待する変化(例: 90日でクエリ群の平均順位20位以内・非ブランドクリック週50)
- 判定日と、外れた場合の次アクション

後付けの成功物語(元記事の構造的弱点)を自分のサイトで繰り返さないための仕組み。

## ② 質ゲート付き出荷

- 「毎日3本」は目標にしない。**情報利得ゲート**(safety-gate.md 5章): 各記事は検索上位10件にない一次情報(自社データ・検証結果・実測値・スクリーンショット)を最低1つ含むこと。含められないネタは書かない
- 本数はゲートの結果として決まる(目安: 週2〜3本)。scaled content abuse リスク(→ 06章§3)を避けつつ、1本あたりの被引用可能性を上げる
- AI引用向け整形(aio-optimization スキル): 冒頭に結論の定義文・出典時点付きの数値文・Q&Aブロック

## ③ 交絡除去した計測

**KPIは「非ブランド検索」「AI引用」「検索起点リード」の3層のみ。** 合計流入・合計問い合わせは知名度・SNSの影響が混ざるためKPIにしない。

1. **GSCブランド分離**: 正規表現フィルタで指名クエリ(社名・個人名・サービス名とその表記ゆれ)を除外した「非ブランドレポート」を毎週自動生成(seo-validity)
2. **UTM規律**: SNS投稿・メール・資料内リンクに必ずUTMを付け、検索起点(=手法の成果)とSNS起点(=発信の成果)を初回接点で分離。フォームに流入元を自動記録
3. **記事コホート測定**: 各記事を公開28日後に判定 — インデックス済みか / 表示回数 / 非ブランドクリック / アシストした転換。1本ごとの限界価値を可視化(元記事の「59本で月21PV/本」を自分のサイトで検出できるように)
4. **AI引用モニタリング**: 狙いクエリに対応する質問セット(10〜20問)を月1回 ChatGPT / Perplexity / AI Overviews に投げ、自サイト引用の有無を記録。AI経由リファラ(chatgpt.com / perplexity.ai 等)もGA4で分離集計

## ④ 判定と刈り込み

週次(30分)+月次(60分)で機械的に判定:

| 状態 | 判定 | アクション |
|---|---|---|
| 表示多 × CTR低 | 直す | タイトル・冒頭リライト(seo-growth) |
| 順位4〜10位のクエリ保有 | 伸ばす | 一次情報の追記で1〜3位を狙う(最も費用対効果が高い帯) |
| 28日で表示ほぼゼロ | 削る | 類似記事へ統合(301)または削除。**負け記事を残すとサイト全体の品質評価を薄める** |
| AI引用ゼロが3ヶ月継続 | 構造を疑う | aio-optimization の引用性チェックリストを再適用 |

## 無名事業者のための権威構築(知名度の代替)

元記事の著者が知名度で無料スキップしている律速段階。構造化データではなくこれが本体:

1. **独自調査・データの公開**: 業界アンケート・ベンチマーク・料金比較の実測など「引用したくなる一次データ」を四半期に1本作り、プレスリリース+関連メディアへ提供。被リンクとAI引用の両方を狙う
2. **エンティティの外部裏付け**: 会社の各種プロフィール(業界ディレクトリ・Googleビジネスプロフィール・登壇・寄稿)を統一表記で揃え、構造化データの `sameAs` から張る
3. **顧客レビュー・事例の第三者掲載**: 自サイトの「お客様の声」より、外部プラットフォーム上のレビューが権威に効く
